An extension is a WebAssembly component of the `tartan:ext@0.1.0` world (`wit/tartan.wit`), published as a package and installed on a repository or an org.

## Packages

A package is a directory with `tartan.json`, `component.wasm` and the migrations its manifest names. `scripts/build-extension.sh <crate> <out>` builds one from a Rust crate.

```json
{
  "id": "rawkode.issues",
  "name": "Issues",
  "version": "0.5.0",
  "api": "tartan:ext@0.1.0",
  "storage": { "scope": "repo", "migrations": ["migrations/0001_init.sql"] },
  "subscribe": [{ "event": "ref.*" }],
  "permissions": { "calls": { "rawkode.issues": ["update"] } }
}
```

`storage.scope` is `repo` (one database per repository) or `org` (one per org). Publish with `POST /-/api/packages` (`manifest`, base64 `component`, `migrations`). An `id@version` never changes: publishing other contents under it answers 409.

## What an extension can do

| Import | Gives |
| --- | --- |
| `sql` | its installation's own SQLite database |
| `kv` | a key-value store in the same database |
| `host` | its configuration, logging, a clock, randomness and ULIDs |
| `effects` | emitting events and setting timers, applied only if the call succeeds |
| `calls` | another installation's tools, when the manifest permits them |

It exports `init`, `on-event`, `on-timer`, `render`, `on-action`, `call-tool` and the rest of the world; the Rust SDK (`sdk/rust/tartan-ext`) supplies defaults.

## Limits

Each call runs in a fresh instance with its own fuel, 128 MiB of memory and 10 seconds. An extension's SQL cannot touch the host's `_tartan_*` tables or run `ATTACH`, `DETACH`, `PRAGMA` or `VACUUM`; during `render` it may only read. `notify` and why-notes answer `unavailable` for now.

## Events

The manifest's `subscribe` patterns decide what reaches `on-event`: a repository's installation receives its repository's events, an org's installation every event in the org. Each event reaches `on-event` once, in order per source; an event the extension fails on is kept as a dead letter and does not block the next. An extension's emitted events appear as `x.<extension-id>.<type>`.

## Calls between extensions

The `calls` import calls another installation's tool, acting for the same principal, when the manifest's `permissions.calls` names the extension and tool and the target is a repository installation in the same org (a repository's installation may only call into its own repository).

## Calling an installation over HTTP

```sh
curl -X POST -H "Authorization: Bearer $TOKEN" \
  localhost:8080/-/api/orgs/acme/repos/api/extensions/rawkode.issues/tools/list -d '{}'
```

Org installations are under `/-/api/orgs/<org>/extensions/<id>/…`. Besides `tools/<tool>` there are `render/<slot>` and `actions/<action>`. Extension errors map to statuses: `denied` 403, `not_found` 404, `invalid` 400, `conflict` 409, `unavailable` 503.
