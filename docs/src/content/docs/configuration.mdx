Extensions are installed and configured only by the CUE package `tartan` committed at a repository's root. There is no install API: a push to `main` that changes it is the only way an extension is installed, upgraded, reconfigured or removed.

```cue
package tartan

extensions: "rawkode.issues": {
	version: "0.5.0"
	settings: fields: status: {type: "select", options: ["todo", "doing", "done"], default: "todo"}
}
```

Each entry under `extensions` is an extension id with an optional `version` and free-form `settings`. Any other key, an invalid id or version, or CUE that does not evaluate makes the configuration invalid.

## A package, not a file

The configuration is every root `*.cue` file that declares `package tartan`, evaluated together the way `cue eval` evaluates a package directory. Name the files as you like and split them as you like; `tartan.cue` is only a convention. Root files of other packages, such as a cuenv `env.cue`, are not part of it, and a repository with no `package tartan` file at its root installs nothing.

With `cue.mod/module.cue`, your module path and language version are used and packages of your module can be imported:

```cue
// cue.mod/module.cue
module: "example.com/acme-api"
language: version: "v0.14.1"

// config/fields/fields.cue
package fields

all: status: {type: "select", options: ["todo", "done"], default: "todo"}

// issues.cue
package tartan

import defs "example.com/acme-api/config/fields"

extensions: "rawkode.issues": {version: "0.5.0", settings: fields: defs.all}
```

The forge reads only what the package needs at the pushed commit: the root's `*.cue` files, `cue.mod/`, and the directories of the module's packages that are imported. Imports of other modules resolve through the forge's CUE registry configuration (`CUE_REGISTRY`). A configuration may read at most 500 files, 64 directories and 4 MiB of CUE.

## When it applies

When `refs/heads/main` moves, the forge loads the configuration at the new commit and applies it. Other branches never apply. When pushes arrive quickly, the latest commit wins.

The file is applied all or nothing. Every entry is checked first: its version is published and its package installs where the file lives. If anything fails, nothing changes and `config.refused` records the problems.

| Change | What happens |
| --- | --- |
| A new entry | the extension is installed: its migrations run, then `init` |
| A new `version` | the extension is upgraded: the new migrations run, then `init` again |
| New `settings` | the installation's configuration changes; its data is untouched |
| A removed entry | the extension is disabled: calls answer 404, its data is kept |
| The entry again | the same installation comes back, with its data |

## The org's configuration

The repository named `tartan` in an org configures the org, with the same kind of package. Each entry there installs an `org`-scoped package on the org, and must have a `version`.

```cue
package tartan

extensions: "rawkode.kanban": {
	version: "0.2.0"
	settings: boards: org: {name: "Everything", field: "status", columns: [{value: "todo"}, {value: "done"}]}
}
```

## Contributing to the org's extensions

An entry without a `version` in a repository's configuration contributes settings to the org's installation of that extension:

```cue
extensions: "rawkode.kanban": settings: boards: api: {field: "status", columns: [{value: "todo"}, {value: "done"}]}
```

An org installation's configuration is its own settings plus `repos`: for each contributing repository, its id, `path` and `settings`. When a contribution changes, the org installation is reconfigured.

## Events

| Event | Source | When |
| --- | --- | --- |
| `config.applied` | repo or org | a configuration was applied; `data.changes` lists what changed |
| `config.refused` | repo or org | a configuration was refused; `data.problems` says why |
| `extension.installed` | repo or org | an extension was installed or re-enabled |
| `extension.upgraded` | repo or org | an installation moved to a new version |
| `extension.configured` | repo or org | an installation's configuration changed |
| `extension.uninstalled` | repo or org | an installation was disabled |
