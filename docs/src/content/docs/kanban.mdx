Kanban installs once per org, from the org's `tartan` repository. It keeps a card for every issue in the org from Issues' events, including issues created before it was installed, and shows them on boards. Boards are defined in configuration: the org's in its `tartan` repository, and a repository's or a project's in that repository.

## A worked example

The org's `tartan` repository installs Kanban and defines org-wide boards:

```cue
// acme/tartan: any root file of package tartan, such as tartan.cue
package tartan

let statuses = [{value: "todo", title: "To do"}, {value: "doing", title: "Doing"}, {value: "done", title: "Done"}]

extensions: "rawkode.kanban": {
	version: "0.2.0"
	settings: boards: {
		org: {name: "Everything", field: "status", columns: statuses}
		web: {field: "status", columns: statuses, scope: {kind: "repo", repo: "acme/web"}}
		state: {field: "state", columns: [{value: "open"}, {value: "closed"}]}
	}
}
```

A repository adds its own boards, and its projects' boards, by contributing settings without a version:

```cue
// acme/api
package tartan

let statuses = [{value: "todo"}, {value: "doing"}, {value: "done"}]

extensions: "rawkode.issues": {
	version: "0.5.0"
	settings: fields: status: {type: "select", options: ["todo", "doing", "done"], default: "todo"}
}
extensions: "rawkode.kanban": settings: boards: {
	api: {name: "API", field: "status", columns: statuses}
	lsp: {name: "Language server", field: "status", project: "crates/lsp", columns: statuses}
}
```

This gives five boards: `org`, `web` and `state` from the org, and `acme/api/api` and `acme/api/lsp` from the repository.

## Board settings

| Key | Meaning |
| --- | --- |
| `name` | the board's title; defaults to its id |
| `field` | the issue field the columns are values of, or `state` for open and closed |
| `columns` | 1 to 12 columns, each `{value, title}`, with distinct values |
| `scope` | org boards only: `{kind: "org"}` (the default), `{kind: "repo", repo: "acme/web"}` or `{kind: "project", repo: "acme/api", project: "crates/lsp"}` |
| `project` | contributed boards only: scope the board to one of the repository's projects |

A contributed board is named `<org>/<repo>/<id>` and is scoped to its repository. An issue without a value starts in the first column; one whose value is not a column is listed as unplaced. A definition that is not a valid board is left out and reported by `list_boards` under `invalid`.

## Moving cards

The `move` tool (and the board's `move` action) moves a card by calling Issues' `update` in the card's repository, which Kanban's manifest permits with `"calls": {"rawkode.issues": ["update"]}`. Moving to a value that is not a column is refused, and so is a card outside the board's scope.

## Tools

`list_boards` (the boards, and the definitions that are not boards), `board` (one board with its cards in columns) and `move`.
